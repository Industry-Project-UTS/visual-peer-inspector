# Remaining-cohort readiness and evidence workbench

## Current decision and scope

The current frozen modes are automatic winner consensus and correspondence-assisted object-bank strongest-two fusion. The original roles remain **1,000 development, 600 calibration and 400 internal-lock scenes**. The new workbench reports the existing sealed 100-scene development cohort. It does not represent 2,000 completed evaluations.

The completed 08N/08O/08P code and scientific artifacts remain unchanged. Every registered compatible 08O and 08P method appears in the comparison tables; a method's highest development score does not replace the frozen decision. Protected results cannot select another scorer, fusion rule, schedule or matcher.

## Completed notebook and future work

The repository contains the completed clean and sanitized executed **09E** notebook, its reusable reporting code, focused tests and sealed aggregate evidence. The 09E builder updates only 09E; it does not modify other notebook stages.

Unexecuted 09/10 adaptations are developed in the separate working project's `development/remaining-evaluation/` stage. They are outside this completed-work integration. The older 09A/B/B1/C/D and 10-series notebooks already present in the repository remain historical P1 implementations and are **not ready for the selected current methods**.

## Current-method cache and prediction hook

`vpi_remaining_evaluation.cohort.predict_cached_cohort` accepts a sealed `vpi-current-method-cohort-cache/v1` package, a sealed current-method freeze and `visual_peer_inspector.web.decision.decide_cached`. It recomputes the canonical sorted opaque-scene membership hash from the actual cache scene list and compares it with the frozen role's model-facing hash. A declared digest plus the correct scene count cannot pass. It strips supplied IDs in automatic mode, restricts every call to its selected views, rejects evaluator fields and writes atomic scene checkpoints plus a final prediction seal. The adapter source digest must match the actual callable's source file. Identical restarts verify and reuse their outputs.

The hook is checked at 1,000/600/400 sizes using explicitly named synthetic membership contracts and label-free fixtures. Those tests do not verify real role IDs or establish calibration/internal-lock execution. Native scene-to-asset attribution, role-cache resource bridges and the new protected evaluator remain unimplemented. A declared asset count does not verify attribution. These remain explicit blockers.

The generated `resource_recipe.json` specifies candidate IDs, RGB checksums, boxes, SAM masks, global DINO features, forward/P1/P2 components for winner consensus, foreground patch arrays for the bank scorer, and crop/grid provenance for projection. Assisted inputs additionally require neutral IDs with explicit dataset-reference or user-confirmed provenance. Missing features must be inventoried before extracting only genuinely absent neural outputs.

## Exposure gate

Set `VPI_EXPOSURE_ROOT` only to a reviewed package containing:

- `artifact_lock.json` sealing the two files below.
- `exposure_ledger.json`: resolved status, nonempty reviewed source digests and the exact original role membership hashes.
- `asset_records.json`: all 273 development, 163 calibration and 109 internal-lock assets, their scene counts, resolved access history and links to reviewed evidence.

Empty, incomplete, changed-membership or unresolved audits fail. Prior protected label/result access blocks an untouched-role confirmation claim. The gate does not repair exposure by reshuffling scenes or dropping assets. A valid exposure audit alone does not certify an unimplemented current-method adapter.

## Rich outputs and privacy

Scientific preparation first copies and seals complete metric, schedule, paired-interval, anomaly-count, majority, failure and identity tables. The technique feature matrix explicitly names mask and correspondence conditions. Role readiness lists missing work and keeps the original denominators.

The inherited `identity_reference_coverage` statistic is invalid: lookups on a default dictionary add absent references before its numerator is computed. 09E preserves its source value in `original_reported_mean`, blanks the usable `mean`, and marks `metric_validity` explicitly. The old sealed evaluation is unchanged. Other ranking metrics and failure counts remain as reported. Separate app-runtime cache revalidation is not merged into these historical comparisons.

Rendering occurs afterward in a separate directory and produces:

- Every registered 08O technique's top-1, AP, Recall@2 and MRR trends with asset-group intervals.
- Primary-schedule technique matrices, three-view schedule sensitivity and failure decomposition.
- Private 1-view diagnostic and 2/3/5-view galleries for both frozen modes.
- Original images, object boxes, consistent IDs, SAM overlays, black-background objects, selected-object highlights and correctly projected coarse patch evidence.
- Per-view score matrices, every retained object's combined score and support count.
- Disclosed post-hoc development failure, tie and missing-view illustrations alongside a fixed first scene.

Ties produce no unique highlighted winner. Missing observations stay blank and explained. Red boxes locate selected objects, not validated defect boundaries. Private scene IDs, scores and images remain under `private/`; shareable artifacts contain aggregate results only. Report figures may be selected later without changing cohort membership or scientific results.

## Execution and recovery

Build with `scripts/build_remaining_evaluation_workbench.py`. Run `scripts/run_remaining_evaluation_workbench.py prepare|report|verify --config PATH`, or execute the clean 09E notebook using the existing notebook executor. The configuration is private; no raw dataset/evaluator paths belong in clean notebooks or publication tables.

Flat and automatically extracted nested package roots are supported; ambiguous roots fail. Input seals, cross-stage bindings, source digests and runtime versions precede work. Rendering checkpoints reuse verified galleries. Reporting, notebook-display or tracking failures do not require another neural run. ClearML publication remains a separate bounded allowlisted step after scientific and report seals; the notebook writes an explicit pending receipt rather than inventing a task link.

`scripts/publish_remaining_evaluation.py prepare` verifies the scientific/report relationship, removes every output from private gallery cells, and preserves only the seven exact aggregate PNGs plus sanitized aggregate outputs in the executed evidence copy. Its self-contained bundle has a separate publication seal. The `publish --bounded` command reuses the existing idempotent ClearML worker with an explicit 09E allowlist; it uploads no raw gallery, scene-level score table, source identity or local path. Failed publication retains a pending receipt without recomputation.
